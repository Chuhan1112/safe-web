# Claude Design 输入包 — Quant Research Console

> 用途：把本项目前端交给 Claude Design（`claude.ai/design`，或任意 Claude 对话中的 Design）生成与迭代界面。
> 安全边界：本文件只包含公开的设计系统与交互需求，**不含**策略公式、参数、私有接口、研究结论、真实持仓数据。
> 与 `web/CLAUDE.md` 的 safe/private 规则一致：这里描述的能力全部由 safe 层可渲染。

## 0. 使用顺序（3 步）

1. 先发 **A. 设计系统种子** + **B. 产品简报**，让 Claude 先复述一遍它的理解，确认没跑偏。
2. 再发 **C. 屏幕任务**：**一次一屏**，并把真实的数据形状写清楚。
3. 用 **D. 迭代指令** 微调。定稿后用 handoff bundle（或 Figma Code to Canvas）落回 Claude Code 实现。

## A. 设计系统种子（先发这段）

```
风格定位：专业、冷静、信息优先的"研究控制台"。不是消费级金融 App。
质感参考：Bloomberg Terminal 的信息密度 + Linear/Arc 的克制。
一句话：这是一个会被同一个人每天开一整天的工具，不是给人浏览一次的落地页。

主题：三套，由同一套 CSS 变量驱动
- light   —— 白天/办公室
- dark    —— 默认，长时间盯盘
- perplexity —— 暖调深棕，低蓝光阅读档

配色（HSL，不写死 hex，用下面的 token 名）：
- light: background 0 0% 98% / foreground 0 0% 20% / primary 207 100% 45%（蓝） / accent 24 96% 53%（橙）
- dark:  background 220 40% 8% / card 220 39% 11% / foreground 210 24% 93% / primary 184 83% 53%（青） / accent 24 94% 58%
- 圆角：--radius 10px（lg）/ 8px（md）/ 6px（sm）
- 主工作区最大宽度 1680px

涨跌色是"市场感知"的 —— 这是本项目最重要的视觉规则：
- 美股：绿涨红跌；A 股：红涨绿跌。
- 所以不要把红/绿写死为"跌/危险"。红绿语义由顶部的市场开关（US / CN）翻转。
- token：data-up 135 78% 39%，data-down 0 84% 60%；CN 模式下两者互换使用。
- 市场标识色：US = #1d4ed8（蓝），CN = #dc2626（红）。

字体：
- 界面：Inter
- 数字：JetBrains Mono —— 价格、收益率、权重、日期、标的代码全部用等宽。
- 有一个 10px（2xs）小号档，专用于表格里的次要标签。

数字排版规则（全站统一，请一次就遵守）：
等宽 · 右对齐 · 千分位 · 显式正负号 · 收益率 2 位小数 · 权重 1 位小数 · 百分比与数值用 tabular-nums。

动效词汇（沿用，不要自创）：
- 时长：press 90ms / snap 140ms / move 220ms / enter 280ms
- 缓动：ease-snap(0.2,0.8,0.2,1) · ease-spring(0.34,1.32,0.44,1) · ease-liquid(0.32,1.5,0.5,1)
- 基调：快、短、有落点。动效用于表达状态变化（数字滚动、抽屉滑入、行高亮），不做装饰性动画。

质感元素（现状）：扁平玻璃面板（半透明 + 1px 边框 + 柔和投影）。注：safe 区当前**没有**光晕、网格背景和噪点（那是我早先的笔误）。
```

## B. 产品简报（接着发这段）

```
产品名：Quant Research Console（量化策略研究工作台）

一句话：给个人量化研究者用的"策略研究 + 盘中监控"控制台，把跑回测、看信号、查数据质量、比实验
收进同一个数据密集的工作区。

用户：1 个专业用户（就是我自己）。每天打开，月度调仓。
不是给散户看的资讯站，是给同一个人反复用的工作台 —— 熟练用户、键盘和鼠标都用、不需要引导教程。

环境：macOS 桌面浏览器，1440–1920px 宽，暗色为主，常驻开着一整天。

最重要的 3 件事（按优先级）：
1. 今天该不该动手？—— 信号：今日目标持仓、买卖动作、风险状态
2. 策略最近怎么样？—— 回测：净值曲线、回撤、指标、交易日志
3. 数据可信吗？—— 数据健康：各标的数据新鲜度、缺口、异常
次要：优化（批量跑参数、可中止、有历史）/ 实验（对比、漂移检测）/ 研究（报告列表）

信息架构：
- 左侧 64px 图标栏（w-16，可展开成带文字），主工作区单页切换，无路由跳转。
- 导航：回测 · 优化 · 健康 · 实验 · 信号 · 分析 · 研究 · 筛选 · 打分 · 数据
- 全局控件：市场开关（US / CN 二选一，切换后全站数字语义与配色跟随）、
  主题开关（light / dark / perplexity）、日期范围选择（带快捷预设范围）。

交互基调（请当作硬约束）：
- 切换 tab 用 CSS 隐藏而不是卸载 —— 后台长任务（优化、全市场扫描）不能因为切页而中断。
- 表格是主角：可排序表头、粘性首列、行内点击进入标的详情。
- 详情一律用右侧抽屉（drawer），不用新页面，保持上下文。
- 每个异步区域都要有骨架屏；空状态必须给出明确的下一步动作。
- 长任务要有进度、可中止、可回看历史。
- 全局只有一个主色强调；不要用颜色堆叠来表达层级，用间距、边框、字重。
```

## C. 屏幕任务（一次一屏）

### 模板

```
## 屏幕任务：<屏幕名>
目的：用户在这屏要完成的判断是什么
必须出现的内容（用真实数据形状，不要 Lorem 占位）：
- …
状态：加载中（骨架屏）/ 空 / 出错 / 有数据
约束：宽度、密度、列数、是否折叠
交互：hover / 点击 / 排序 / 抽屉 / 键盘
不要：明确排除的东西
```

### 例 1 — 信号页

```
## 屏幕任务：信号页（Signals）
目的：30 秒内回答"今天该不该动手、动哪些"。

必须出现的内容：
- 顶部状态条：当前市场（US）、策略名、信号日期、风险状态（例："熔断中：暂停开仓"）
- 目标持仓表，列：标的 / 当前权重 / 目标权重 / 权重差额 / 动作 / 最新价 / 1 日涨跌
  示例行：NVDA · 0.0% → 4.2%（+4.2%）· BUY · $187.42 · +1.83%
- 动作筛选器（全部 / 买入 / 卖出 / 持有），每类带计数
- 每行可展开"为什么"：打开信号解释抽屉，含综合打分、动量排名名次、命中了哪条规则
- 空仓特殊态：无持仓时显示"立即建仓"的目标组合 CTA

状态：加载中 / 今日无调仓（全 HOLD）/ 熔断中 / 有买卖
约束：1440px 宽下 8 列不出现横向滚动；数字全部等宽右对齐；涨跌色跟随市场开关。
不要：做成"投资建议"式的大卡片堆叠；不要饼图；不要圆环图。
```

### 例 2 — 回测页

```
## 屏幕任务：回测页（Backtest）
目的：判断一个策略最近的表现是否还成立。

必须出现的内容：
- 净值曲线：面积图，低饱和渐变，可叠加对比基准；多策略对比最多 6 条线
- 净值 / 回撤切换；hover 出十字线 + 浮层（日期、净值、回撤、当时的持仓快照）
- 指标网格：年化 / 最大回撤 / 夏普 / 卡玛 / 胜率 / 换手率 —— 大数字 + 小标签 + 相对上期的变化箭头
- 诊断区：分段表现、回撤区间列表
- 交易日志表：按日期分组，动作 BUY/SELL/HOLD，标的、价格、数量、权重变化

状态：从未跑过（引导）/ 跑中（进度条 + 已用时）/ 完成 / 失败
约束：曲线区域在窄屏可变矮但不能变形；指标网格 6 列 → 3 列 → 2 列。
不要：3D、发光、拟物化仪表盘。
```

## D. 迭代指令（直接抄）

- `把这一屏的信息密度提高一档：字号不变，压缩行高与间距，一屏多放 5 行数据。`
- `现在这版偏消费级金融 App。我要研究工具：去掉装饰性插画和渐变，换成克制的边框 + 等宽数字。`
- `给出同一屏的 light 与 dark 两版，并列出两版用到的全部颜色 token 名称与值。`
- `补上右侧详情抽屉：头部（标的 + 最新价 + 涨跌 + 市场标签）、K 线区域占位、关键指标、底部操作条。`
- `把加载中（骨架屏）/ 空 / 出错三个状态也画出来。`
- `同一个屏幕给出 1440px 和 1920px 两种布局，说明哪里变宽、哪里换行。`
- `把这块区域的 hover / focus / 选中 三种状态补全，focus ring 要可键盘操作。`
- `导出 handoff：说明每个区域对应的 React 组件名、props 和用到的 token。`

## E. 避坑清单

1. **不贴策略内部**：用"趋势过滤 + 动量排序 + 风险平价仓位"这类抽象说法，不要贴公式、参数、私有接口路径。
   （这正是 `web/` 仓库存在的意义：只放 UI 原语、布局、交互实验和 mock 数据。）
2. **不贴真实持仓/资金**：用形状相同、数字虚构的 mock。
3. **一次一屏**：别把 9 个页面一次全要，Claude 会平均用力、每屏都平庸。
4. **一开始就给视口宽度**：不给宽度它会默认按手机端思路做。
5. **要 token 名，不要让它自由挑 hex**：否则跨屏颜色会对不上。
6. **让它先复述理解再出图**：第一版就节省一轮返工。
7. **数字排版规则第一轮讲清**：等宽 / 右对齐 / 2 位小数。不然后面每屏都要重讲。
8. **涨跌色不要写死红绿**：它是市场相关的，写死了 CN 模式就全错。
