# 给设计方的回复：这批做什么 + 列宽预算（按代码推算）

## 一、下一步按这个顺序（一次做完这批）

**先做 token 化**（成本最低、收益最大）。做法：在画板顶部加一个 `:root { ... }` 变量块，
把三主题的色值定义一次，之后所有颜色写 `hsl(var(--primary))` / `hsl(var(--data-up))` 这种形式。

理由：后面每一屏都会复制这一版的写法。这一版是散落的 hsl 值，下一批的加载中、出错、抽屉、全 HOLD
就会一起复制这个毛病，等落到代码时我得手工反查四屏。现在花十分钟补上，后面全省了。
画布照样能渲染 —— 变量块就在同一个文档里。

**然后做"状态三件套"，它们在同一个屏幕骨架下，一次做完比分开做省事：**
1. 加载中（骨架屏）
2. 出错
3. 今日无调仓（全 HOLD）

**抽屉 + 展开「为什么」放下一批单独做** —— 它们是新的信息层级（带指标、打分、规则命中），
工作量和前面三态不是一个量级，混在一批里会两头都做不深。

## 二、列宽预算（1440px）

你提到没确认 8 列会不会横向滚动。这个不用靠目测，按代码里的布局常量能直接算：

```
1440  视口
 −64  图标栏（w-16，md+ 常驻）
  −1  图标栏右边框
=1375
 −64  页面容器内边距（lg: px-8，两侧各 32）
=1311  表格可用宽度
```

8 列每列左右各 16px 单元格内边距（`p-4` / `px-4`）→ 纯内边距 256px，**剩 1055px 给内容**。

单值宽度（JetBrains Mono 每字符 0.6em；表格默认 14px，即 8.4px/字符）：

| 内容 | 字符数 | 宽度 |
|---|---|---|
| `$187.42` | 7 | 59px |
| `+1.83%` | 6 | 50px |
| `+4.2%` | 5 | 42px |
| `0.0%` | 4 | 34px |
| `NVDA` | 4 | 34px |
| `BUY` 标签（含描边内边距） | — | ~65px |
| 「为什么」图标按钮 | — | ~36px |

8 列内容合计 ≈ 353px，加内边距 256px ≈ **609px**。**余量约 700px。**

结论：**你不需要为宽度做任何妥协。** 与其压字号，不如把行高从 40px 提到 48px，
或者把副信息（名称、持仓天数）放进标的格的第二行 —— 空间足够。
真正开始横向滚动要窄到 ~740px 以下，而那时布局已经切到移动端底部导航了。

（说明：以上是按 `App.tsx` 的 flex 布局 + `PageContainer` 的 `lg:px-8` + `ui/table.tsx` 的
`p-4`/`px-4`/`h-10` + JetBrains Mono 字宽推算的，不是实机渲染数值。落地后我会用无头浏览器实测复核。）

## 三、两条会影响成型质量的约束

1. **骨架屏必须用和真实表格完全相同的列宽与行高。** 否则数据到达的一瞬间列会跳、行会抽。
   现有实现的骨架屏就是按这个要求做的，请沿用同样的列宽。
2. **表头规格**：10px、大写、`letter-spacing: 0.01em`、`muted-foreground` 色。
   **行高**：当前实现是 40px，单元格内边距 16px。你如果改了行高，请在交付说明里写出新值，我按它改代码。
